# تشغيل جهاز قياس العسل الحقيقي (Arduino Uno)

## الحساسات المدعومة في هذا المسار

- TCS34725: قراءات RGB الخام.
- GY-ML8511: قراءة UV التناظرية الخام عبر ADC.
- MLX90614 / GY-906: درجة حرارة الجسم المقاسة بالأشعة تحت الحمراء.

هذا المسار لا يدّعي دعم NeoSpectra أو AS7341 أو MLX90640 أو HX711 أو BME688؛ فهذه القطع ليست ضمن التوصيل الحالي الموثق. لا تُحوّل RGB إلى أطياف متعددة القنوات، ولا تُحوّل استجابة ML8511 إلى طيف امتصاص أو تركيز HMF دون طريقة قياس ومعايرة مرجعية.

## بروتوكول Arduino التسلسلي

اضبط Arduino على 9600 baud واستقبل الأمر:

`START\n`

ثم أرسل سطراً لكل قراءة:

```text
COLOR_DATA,<red>,<green>,<blue>
UV_DATA,<adc_raw_0_to_1023>
IR_DATA,<object_temperature_c>
```

يمكن إرسال `IR_DATA,<object_temperature_c>,<ambient_temperature_c>` أيضاً؛ يعتمد الخادم درجة حرارة الجسم فقط في هذه المرحلة.

## تثبيت وتشغيل محلي

1. ثبّت Python 3 على الجهاز الذي يتصل به Arduino.
2. من مجلد `backend` نفّذ:
   `python -m pip install -r hardware/requirements.txt`
3. انسخ `.env.example` إلى `.env` واضبط:
   - `SERIAL_PORT=COM5` (استخدم المنفذ الفعلي الظاهر في Device Manager).
   - `SERIAL_BAUD_RATE=9600`.
   - `HARDWARE_SCAN_SECONDS=23`.
   - `ADC_REFERENCE_VOLTAGE` فقط بعد قياس/تأكيد جهد مرجع ADC الفعلي.
4. شغّل قاعدة البيانات ثم نفّذ `npm run prisma:generate` و `npm run prisma:push`.
5. شغّل الخادم من مجلد `backend` ثم افتح الواجهة. نفّذ اختبار الفحص والجهاز موصول.

## قواعد السلامة العلمية

- لا يوجد وضع محاكاة تلقائي. تعذر الاتصال أو غياب أي حساس يفشل الفحص بدلاً من اختلاق قراءات.
- نجاح الاتصال يعني أن قراءات الحساسات وصلت فقط؛ ولا يعني أن العينة أصلية أو خالية من الغش.
- لا تصدر شهادة نقاء ولا نسبة ثقة أو HMF أو جلوكوز أو فركتوز أو رطوبة من هذه الحساسات وحدها.
- لا بد من معايرة موثقة ومقارنة عينات مع مختبر مرجعي قبل تقديم تصنيف جودة أو أصالة.
- لتشغيل الخادم داخل Docker يلزم تمرير منفذ USB/Serial إلى الحاوية. على Windows، أبسط مسار أولي هو إبقاء Backend على المضيف وتشغيل PostgreSQL عبر Docker، أو إعداد تمرير USB مناسب صراحةً.
